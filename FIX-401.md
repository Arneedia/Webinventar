# 🔧 Fix für 401 Unauthorized Problem

## Das Problem
Die Datenbankverbindung funktioniert (`tsx scripts/test-db-connection.ts` ✓), aber `npm start` gibt 401 Fehler.

## Die Ursache
**Next.js lädt `.env.local` in Production NICHT automatisch!**

Das Test-Script verwendet `dotenv/config` und funktioniert, aber Next.js in Production ignoriert `.env.local`.

## Die Lösung (2 Optionen)

### Option 1: Verwende `npm run start:prod` (EMPFOHLEN)

```bash
# Auf dem Ubuntu Server:
npm run build
npm run start:prod
```

Das neue `start:prod` Script lädt `.env.local` explizit.

### Option 2: Verwende Systemumgebungsvariablen

```bash
# Setze die Variable permanent
echo 'export DATABASE_URL="postgresql://user:password@localhost:5432/webinventar"' >> ~/.bashrc
source ~/.bashrc

# Dann normal starten
npm run build
npm start
```

## Für PM2 (Production)

```bash
# Stoppe alte Instanz falls vorhanden
pm2 delete webinventar

# Starte mit neuem Befehl
pm2 start npm --name "webinventar" -- run start:prod

# Logs prüfen
pm2 logs webinventar

# Sollte zeigen:

# [Auth] getCurrentUserFromRequest - Token vorhanden: true
```

## Schnelltest

```bash

# 2. Start mit neuem Befehl
npm run start:prod

# 3. Im Browser anmelden und DevTools öffnen
# Keine 401 Fehler mehr! ✓
```

## Problem: "Session gefunden: false"

Wenn du in den Logs siehst:
```
[Auth] Token vorhanden: true
[Auth] Session gefunden: false
```

**Ursache:** Die Session ist abgelaufen oder existiert nicht mehr in der DB.

**Lösung:**

```bash
# 1. Bereinige alte Sessions
tsx scripts/cleanup-sessions.ts

# 2. Im Browser: Lösche Cookies oder melde dich ab
# Browser DevTools → Application → Cookies → Lösche "session" Cookie

# 3. Melde dich neu an
# Jetzt sollte es funktionieren!
```

**Alternative:** Lösche alle Sessions und melde alle Benutzer ab:

```bash
# In der PostgreSQL-Konsole:
psql -U user -d webinventar -c "DELETE FROM \"Session\";"

# Oder mit Prisma Studio:
npx prisma studio
# → Session Tabelle → Alle löschen
```

## Was wurde geändert?

```typescript

```

Aber Next.js macht das in Production nicht automatisch!
